## 🔄 <span style="color: #6c5ce7;">Миграция на Realm</span> 📈

<div align="center">
  <h3>🚀 План перехода на Realm</h3>
</div>

Текущая реализация использует кастомное JSON-based хранилище (`SwiftDataChatStore`). Для улучшения производительности и надежности планируется переход на **Realm**! 🌟

### <span style="color: #00b894;">Что нужно сделать для интеграции Realm:</span>
1. **📦 Добавить Realm в проект** через Swift Package Manager
2. **🗂️ Создать Realm модели** для Chat, Message и других сущностей
3. **💾 Реализовать RealmChatStore** взамен SwiftDataChatStore
4. **🔄 Миграция данных** из JSON в Realm
5. **🔧 Обновить DI-контейнер** для использования новой реализации
6. **🧪 Тестирование** новой реализации

📖 Подробные шаги см. в файле **[MIGRATION_TO_REALM.md](MIGRATION_TO_REALM.md)**.

### <span style="color: #00cec9;">📥 Установка Xcode</span>
1. **🛍️ Откройте App Store** → установите **Xcode** → запустите его один раз, соглашайтесь с лицензией
2. **✅ Убедитесь, что версия Xcode ≥ <span style="color: #d63031;">15.0</span>**

### <span style="color: #a29bfe;">📥 Клонирование проекта</span>
```bash
git clone https://github.com/nepovtor/Mobile-Messenger-IOS.git
cd Mobile-Messenger-IOS
```

### <span style="color: #fd79a8;">📦 Зависимости</span>

#### <span style="color: #00b894;">Вариант A — без CocoaPods</span> 🚀
Ничего ставить не нужно: **SPM** подтянет зависимости автоматически при сборке! ✨

#### <span style="color: #e17055;">Вариант B — с CocoaPods</span> 📦
1. **🍺 Установите Homebrew** (если нет):
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```
2. **📱 Установите CocoaPods**:
   ```bash
   brew install cocoapods
   pod --version   # должно показать номер версии
   ```
3. **🔧 В корне проекта выполните**:
   ```bash
   pod install
   ```
4. **📂 Открывайте `.xcworkspace`, а не `.xcodeproj`**

> ⚠️ Если при `pod install` получите SSL-ошибку — попробуйте другую сеть! 🌐

### <span style="color: #6c5ce7;">⚙️ Конфигурация окружения</span>
Скопируйте пример конфигурации и укажите собственные ключи и эндпоинты:
```bash
cp Config/Config.example.xcconfig Config/Config.xcconfig
```

### <span style="color: #fdcb6e;">📱 Открытие в Xcode</span>
- **📦 Если использовали CocoaPods**: откройте `MobileMessengerIOS.xcworkspace`
- **🚀 Если нет Podfile**: откройте `MobileMessengerIOS.xcodeproj`

### <span style="color: #00cec9;">▶️ Запуск в симуляторе</span>
1. **🎛️ В верхней панели Xcode** выберите **Scheme**: `MobileMessengerIOS`
2. **📱 Рядом выберите симулятор** (например, **iPhone 17**)
3. **▶️ Нажмите Run** или `Cmd + R`

### <span style="color: #a29bfe;">📱 Запуск на реальном устройстве</span> (опционально)
1. **🔌 Подключите iPhone** по кабелю → нажмите **Trust** на устройстве
2. **👤 Xcode → Settings → Accounts** → добавьте свой Apple ID
3. **📂 В Project Navigator** → выберите **Target `MobileMessengerIOS`** → **Signing & Capabilities** → выберите **Team**
4. **📱 Выберите свой iPhone** в списке устройств → **Run**

### <span style="color: #fd79a8;">💡 Подсказки и решение проблем</span>
- **🧹 Очистить кэш сборки**: **Product → Clean Build Folder** (`Cmd + Shift + K`)
- **🐛 Если `pod` не найден**: закройте и откройте Terminal
- **🔑 Если не запускается из-за подписи**: включите **Automatically manage signing**
- **📱 Если Xcode ругается на iOS-версию**: выберите устройство с iOS **17+**
- **⏳ Если SPM завис**: **File → Packages → Reset Package Caches**

1. В верхней панели Xcode выберите **Scheme**: `MobileMessengerIOS`.
2. Рядом выберите симулятор (например, **iPhone 17**).

2. Xcode → **Settings → Accounts** → добавьте свой Apple ID.
3. В Project Navigator → выберите **Target `MobileMessengerIOS` → Signing & Capabilities** → выберите **Team**.
4. Выберите свой iPhone в списке устройств → **Run**.

  ```bash
  echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc
  source ~/.zshrc
  ```

* Если не запускается из-за подписи: включите **Automatically manage signing** и выберите **Team**.
* Если Xcode ругается на iOS-версию симулятора: выберите устройство с iOS **17+**.
* Если SPM завис: **File → Packages → Reset Package Caches**.

## 🛠️ <span style="color: #fd79a8;">Серверная разработка</span> 🚀

<div align="center">
  <h3>🌐 <span style="color: #0984e3;">Backend инфраструктура</span></h3>
  <p>В репозитории добавлен <strong>рабочий каркас backend'а</strong> (NestJS) в папке <code>server/</code>! ✨</p>
</div>

Он закрывает **базовую инфраструктуру** для интеграции с мобильным клиентом и может запускаться локально! 🏃‍♂️

### <span style="color: #00b894;">🎯 Минимальный стек</span>
- **<span style="color: #e84393;">TypeScript + NestJS</span>** для HTTP/WebSocket API
- **<span style="color: #6c5ce7;">SQLite</span>** по умолчанию для локального запуска и smoke-тестов
- **<span style="color: #fdcb6e;">PostgreSQL / Redis / MinIO / Redpanda</span>** уже подготовлены в `docker-compose.dev.yml`
- **<span style="color: #00cec9;">REST + WebSocket</span>** точки входа для интеграции и real-time сценариев
- **<span style="color: #a29bfe;">Контрактно-ориентированная структура DTO</span>** как база для OpenAPI/AsyncAPI

### <span style="color: #fd79a8;">⚡ Быстрый старт локально</span>
<div align="center">
  <h4>🚀 <span style="color: #0984e3;">Запуск backend'а за 5 минут!</span></h4>
</div>

1. **🐳 Поднимите инфраструктуру в Docker** (PostgreSQL, Redis, MinIO, Kafka/Redpanda):
   ```bash
   docker compose -f server/docker-compose.dev.yml up -d
   ```
2. **⚙️ Настройте переменные окружения**:
   ```bash
   cd server
   cp .env.example .env
   ```
3. **📦 Установите зависимости** (Node 20+, npm):
   ```bash
   npm install
   ```
4. **▶️ Запустите backend в watch-режиме**:
   ```bash
   npm run start:dev
   ```
5. **✅ Проверьте точки входа**:
   - 🌐 REST префикс: `http://localhost:8080/api`
   - ❤️ Healthcheck: `GET http://localhost:8080/api/health`
   - 📋 Версия сборки: `GET http://localhost:8080/api/version`
